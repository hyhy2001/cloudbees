RX AUTO Tool Guide

1. Overview

Package V5 — RX AUTO is a modular automation framework for RX verification workflows. It orchestrates:

  • RXEWS environment population (Trunk IP / Common IP)
  • RX run execution with SVN revision tracking
  • Queue-based job scheduling on LSF
  • Dashboard server generation (Gunicorn) with custom rxqor support
  • Redmine report integration and analysis
  • Module mapping and submit list management
  • Ticket panel for issue tracking and snapshot analysis
  • Custom rxqor wrapper via USER_LIB

The system is driven by a Makefile + template bash scripts. Templates use envsubst to inject environment variables and produce runtime scripts. Users configure variables once in setup scripts, then all generated scripts are consistent.

For full variable reference, see README.md or run make help

3. Core Architecture

Template → Generate → Execute

Setup script (general_setup / auto_setup / server_setup)
  ↓ calls
Makefile target (setup_run_cmd / setup_for_auto / ...)
  ↓ uses
Template (*_core.bash / *_template.bash)
  ↓ envsubst (inject variables)
Generated script (01_*.bash / 02_*.bash)
  ↓
Runtime execution / Queue / Server

Dual Mode: Trunk IP vs Common IP

Every setup script runs targets twice:

  1. For Trunk IP (default RUN_TYPE=TrunkIP)
  2. For Common IP (RUN_TYPE=Trunk)

When RUN_TYPE=Trunk, the Makefile overrides:

  • SVN URLs → Common trunk paths
  • Run/detect/queue/go_rx_auto scripts → 02_* variants
  • Dashboard server config → Common_IP server
  • Module lists → common module lists
  • AUTO_PROCESS dir → Common_IP

5. Prerequisites

Before running setup scripts, apply RXEWS Makefile modifications (Section 4) and populate the RXEWS environment using the following scripts.

ENTRY my_ride_setup

Activates the RiDE (Renesas Design Environment) shell environment.

source /design01/shura_pd_vf/DE/shura_ride_wk22.git/src/ride/templates/ride/activate.csh

Must be sourced (not executed) before any RX operation.

ENTRY my_cmd — Populate RXEWS (Trunk IP)

Creates and populates the RXEWS working directory for Trunk IP flow.

#!/bin/sh
set RXEWS_FOLDER = "rxews_trunk_ip_vnet_"

mkdir ${RXEWS_FOLDER}
source set_permission `pwd`/${RXEWS_FOLDER}
rdfspop --workflow=pop_ews \
  --module-filter=None \
  --local-repo=/design01/shura_ipride_vf/trunk_IP/VNET \
  --ews-dir=${PWD}/${RXEWS_FOLDER} \
  --svn-repo=http://masl002.eda.renesas.com/svn/shura/common/shura/trunk_IP/VNET/ \
  --pop-ip-units --use-ss-flist --is-ip-repo

The resulting folder path becomes TRUNK_IP_RXEWS_RUN_DIR_PATH.

ENTRY my_cmd_for_common — Populate RXEWS (Common IP)

Creates and populates the RXEWS working directory for Common IP flow.

#!/bin/sh
set RXEWS_FOLDER = "rxews_trunk_vnet_wk_"

mkdir ${RXEWS_FOLDER}
source set_permission `pwd`/${RXEWS_FOLDER}
rdfspop --workflow=pop_ews \
  --module-filter=None \
  --local-repo=/design01/shura_ipride_vf/99_users/phongngo/trunk/VNET \
  --ews-dir=${PWD}/${RXEWS_FOLDER} \
  --svn-repo=http://masl002.eda.renesas.com/svn/shura/common/shura/trunk/VNET \
  --pop-ip-units --use-ss-flist

Note: --is-ip-repo is not used. Resulting path becomes COMMON_RXEWS_RUN_DIR_PATH.

ENTRY set_permission

Sets correct file/directory permissions. Called by my_cmd and my_cmd_for_common.

source set_permission /path/to/rxews_folder

UI clicks "Update" for a tool/workflow
  |
  POST /api/start?tool=rxvcs&workflow=rtl_elab&reports_dir=...
  |
  Server: spawn Process(job_worker)
    |-- Build cmd: python3 -u new_rxqor --local-report --tool=... --ws-dir=... --reports-dir=...
    |-- Run subprocess with SIGTERM/SIGKILL on timeout
    |-- Write output to /tmp/rx_update_jobs/<job_id>/output.log
    `-- Write status to /tmp/rx_update_jobs/<job_id>/status.json
  |
  UI polls GET /api/status every few seconds (shows live log)
  UI sends POST /api/heartbeat every HEARTBEAT_MS (default 5s)
  |
  If no heartbeat > LEASE_SECONDS (120s) -> auto-cancel (owner disconnected)
  If runtime > MAX_JOB_SECONDS (3600s) -> timeout kill
ParameterDefaultEnv Override
Max job time3600s (1 hour)JOB_TIMEOUT_SECONDS
Heartbeat lease120sJOB_LEASE_SECONDS
Heartbeat interval5000msJOB_HEARTBEAT_MS
Log tail size200KBLOG_TAIL_BYTES
Job state dir/tmp/rx_update_jobsJOB_STATE_DIR

When user views /module_summary/<module_name>:

1. Create temp dir: JSON_BASE/M_TEMP/<module_name>/
2. Symlink module source: ENV_BASE/<module_name> -> temp dir
3. Run: new_rxqor --local-report --ws-dir=<symlink> --reports-dir=<temp>/M_RP
4. Read generated Design.json
5. Render module_summary.html
6. Cleanup symlink

Custom rxqor Integration

new_rxmetrics.py provides the custom rxqor command used by:

  • /module_summary/ route — calls new_rxqor --local-report per module
  • /api/start job worker — calls new_rxqor --local-report --tool=... --workflow=... for batch updates
  • run_rxqor.bash (generated wrapper) — used by scheduled DB updates via scheduler.py

The wrapper injects USER_CUSTOM_SRC into PYTHONPATH so Python resolves new_rxmetrics first. No Python clone needed.

Step 3: Add New Route (Optional)

If your new tool needs a custom view beyond the standard summary/lint templates:

3a. Add route in app7.py:

# Pattern: follow existing route conventions
@app.route('/newtool_custom_view')
def newtool_custom_view():
    # 1. Get query parameters
    module = request.args.get('module')
    directory = request.args.get('directory')
    tool = request.args.get('tool')
    workflow = request.args.get('workflow')
    project_name = request.args.get('project').strip()
    unit_type = request.args.get('unit').strip()

    # 2. Load Design.json
    json_base = app.config.get("JSON_BASE", "")
    if not json_base:
        return "Server misconfigured: JSON_BASE not set", 500

    json_file_path = os.path.join(json_base, app.config[f"{tool}_{workflow}"])
    try:
        if os.path.exists(json_file_path):
            with open(json_file_path, "r") as f:
                design_data = json.load(f)
        else:
            design_data = None
    except (FileNotFoundError, json.JSONDecodeError) as e:
        print("Error while parsing json file")

    # 3. Render template with data
    base_url = request.host_url.rstrip("/")
    return render_template(
        'newtool_custom.html',
        design=design_data[project_name][unit_type][tool][workflow][directory],
        run_dir=directory,
        workflow=workflow,
        tool=tool,
        base_url=base_url,
        project_name=project_name,
        unit_type=unit_type
    )

14. How to Extend

14.1 Add New Script Flow

  1. Create template: RX_AUTO/_new_template.bash with ${VAR} placeholders
  2. Add Makefile target with envsubst generation
  3. Add chmod +x for generated output
  4. Add to parent target or setup script

14.2 Add New RUN_TYPE

  1. Define new variable set in Makefile
  2. Add ifeq ($(RUN_TYPE),NewType) block
  3. Override all relevant variables
  4. Add corresponding calls in setup scripts

14.3 Add New Dashboard Module

  1. Create folder under SV_GUNICORN/NewModule/
  2. Add _gunicorn.conf.core.py + _run_server_core templates
  3. Add Makefile target for generation
  4. Add call to server_setup.bash

14.4 Add New Report Tool

  1. Create core template under REDMINE_ITC/redmine_auto_report_v2/
  2. Add envsubst generation in Makefile
  3. Register in setup_check_rp_cmd if applicable

14.5 Add Custom rxqor Module

  1. Place custom Python module in SV_GUNICORN/USER_LIB/
  2. _run_rxqor_core.bash template auto-injects USER_CUSTOM_SRC path
  3. Generated run_rxqor.bash uses original Python + custom PYTHONPATH
  4. No Python clone needed — other users remain unaffected

16. Important Notes

  • Never edit generated scripts (01_*, 02_*) — always modify templates
  • Makefile is the single source of truth for all paths and logic
  • After changing any template, re-run the corresponding make target
  • COMMON_RUN_TYPE="Trunk" is a fixed value — do not change
  • Keep LOCAL_PYTHON pointing to Python 3.10+
  • Use make help to display README.md in terminal
  • Setup scripts run targets for both modes automatically
  • USER_LIB/ contains custom rxmetrics — run_rxqor.bash injects this via PYTHONPATH, no Python clone needed
  • Apply RXEWS Makefile modifications (Section 4) before running setup scripts
